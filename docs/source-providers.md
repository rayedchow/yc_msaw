# Source providers: what is implemented and what is connected

**Connected live: none.** The pivot has not been deployed. Every provider below is implemented in code and tested
only against synthetic fixtures (fake provider APIs, PGlite, a local PostgreSQL 18 cluster). Account setup that
needs a human is listed at the end.

Terms used in the tables:

- **Content**: the provider's data is exported as files.
- **Raw**: the stored provider record, post-redaction.
- **Bytes**: exact binary bytes.
- **Coverage** is what the provider reports through `sources_status`. `complete` is reported only when the module
  can prove it; anything unreported shows `pending` or `unreported`.

## Google (runtime `providers/google-auth`, `gmail`, `calendar`, `google-contacts`, `google-docs`)

| Source | Paths | What is captured | Coverage and limits |
|---|---|---|---|
| Google auth | none | Direct OAuth, domain-wide delegation, or Composio, resolved per account | DWD scopes other than Gmail stay `pending` until a job uses them. Composio accounts work for Gmail, Calendar and Contacts (proxied transport). The Docs/Drive lane needs a bearer, so for Composio accounts it is `blocked` or fails per account; it is never silently skipped. |
| Gmail | `sources/gmail/<mailbox>/…` | The whole mailbox, resumably: readable pages with full bodies, raw message JSON, `.eml` (withheld when redaction changed the payload), attachment bytes (≤ 50 MiB), threads, raw history pages, `state.json`. Labels and deletes are applied in order. | Per mailbox, `complete` only after the current full pass finishes and history was checked within 15 minutes. No push (`users.watch`). Mail deleted before the first pass is unrecoverable. |
| Calendar | `sources/calendar/accounts/<mailbox>/calendars/<id>/events/…`, plus the donor `sources/calendar/<yyyy>/<mm>/*.md` | Per-mailbox event snapshots (exact jsonb), append-only revisions with raw diffs, calendar metadata. Resumable full sync, 410 reset without losing snapshots, removal tombstones, push channels with polling fallback. | `complete` = current state complete; edit history only from first capture. The shared mirror buckets by UTC date (raw keeps zoned times). |
| Contacts | `sources/google-contacts/accounts/<mailbox>/{connections,other-contacts}/<id>.{json,md}` | People API connections and other contacts, incremental via sync tokens, merges and deletions tracked, revisions with diffs. Synced every 15 minutes. | Photos are not requested. A missing `contacts.other.readonly` blocks only that endpoint. |
| Docs / Drive | `sources/google-docs/…` | Docs: native document and per-tab JSON (never `contentUri`), image bytes, permissions, snapshot diffs, the OT changelog (raw `/revisions/load` pages, parsed ops, 5-minute per-user sessions with true-order before/after text, suggestions, tabs). Sheets/Slides: `files.export` plus native JSON. Other Drive files: exact bytes (size caps). PDFs go through the donor drive-pdf binary lane. A **full Drive inventory** per mailbox (My Drive, shared-with-me, every shared drive) checkpoints files that never changed after connect. | `drive-inventory` is `complete` only after a gap-free listing of every roster mailbox. `docs-history` relies on an undocumented, writer+-gated endpoint and is `blocked` under Composio. A partial changelog never advances. Access lost in one mailbox does not tombstone a file another mailbox still sees. Table/list/image edits are recorded but not replayed into text. |

## Devices

| Source | What is captured | Coverage and limits |
|---|---|---|
| iMessage (Mac uploader) | The bundled uploader protocol (`/api/imessage/ingest`, `sync-contacts`, `local-status`, `command`, `command/ack`) on the runtime public host. Canonical, legacy and GUID identity with alias dedupe. Edit and unsend history. Durable command queue. Per-chat projections. | `complete` only after a validated all-history source-sync receipt. Attachments are metadata only (`partial`). yc_msaw confirms every request and revocation is immediate. Nothing was installed or captured. |

| Coding sessions (Codex / Claude Code, Mac agent) | The bundled agent's ingest and command protocol on the runtime host. A server-minted `gcs_` device key, with yc_msaw confirming every request; revocation is immediate and the lane fails closed. Normalized sessions are stored with immutable versions and **no text truncation**, at `sources/coding-sessions/<provider>/<yyyy-mm>/<session>.{json,md}`. `complete` only after a full-inventory source_sync receipt. These are redacted normalized transcripts, not raw JSONL. |

| Office audio (Mac room collector) | **Transcript-only, consent-gated.** No audio, STT or voice profiling. A server-minted `goa_` key is confirmed by yc_msaw on every request. A session is stored only when **an admin granted consent** to every named participant (`POST /v1/sources/office-audio/consents`). Body-claimed consent is never authority, so forged, missing or revoked consent rejects the session (counted in coverage). Revoking with `deleteCaptured` tombstones captured sessions. Files are at `sources/office-audio/<yyyy-mm>/<session>/{session.json,transcript.md}`. |

## Other providers

Each provider's per-integration agent results are recorded here as they are merged. Baseline export (raw ledger
plus the donor mirror projection) exists for Confluence, Jira, GitHub, Bitbucket, Slack, Notion and Granola.

| Provider | State |
|---|---|
| Confluence | **Implemented.** Two lanes. (1) The donor Nango records lane (current page/comment state; raw ids keyed by Confluence version), with page files ordered by version and stale moved/deleted copies cleaned up. That cleanup is disabled when a tenant has several Confluence connections, and coverage says so. (2) A REST deep sweep through the Nango proxy (`confluence.sweep`, every 5 min) at `sources/confluence/_sites/<cloudId>/<connectionId>/…`: spaces and permissions, pages including archived and trash, blog posts, **every version body**, ADF, footer/inline comments with replies, restrictions, and attachment bytes. Deletions are 404-confirmed. Retry-After is persisted per Atlassian bucket, and listings are resumable. History is reported partial (older comment and attachment versions are not fetched). |
| Jira | **Implemented.** Two lanes. (1) The donor Nango lanes, unchanged (record sync plus the `nango.proxy_details` sweep, byte-identical donor keys, `sources/jira/<PROJECT>/<KEY>.md`), with the old-key file of a moved issue and deleted issues removed at export, keyed by the numeric issue id. That cleanup is disabled when a tenant reaches several Jira sites, and coverage says so. (2) A REST deep sweep through the Nango proxy (`jira.sweep`, every 5 min) at `sources/jira/_sites/<cloudId>/<connectionId>/projects/<KEY>/issues/<ISSUE-KEY>/…`: every field, ADF rendered by the donor converter, **every changelog entry** (paged past the subset search embeds), every comment (edits kept as raw observations; deletions 404-confirmed), and attachment bytes. Projects come from a per-connection selection (`GET/PUT /v1/sources/jira/selection`; default all browsable). Moves keep the numeric id and delete the old paths. A 404 is a deletion only with project browse permission and no security level/visibility restriction; otherwise the item is kept and labelled no longer readable. Retry-After is persisted per Atlassian bucket (OAuth app × site); listings and the relative-JQL delta are resumable, and the watermark advances only after a complete search. History is partial (Jira does not expose earlier comment bodies). Comment edits that do not bump the issue appear at the next full pass (12 h). |
| GitHub | **Implemented.** The donor Nango lanes are unchanged (issues, PRs, comments; slim records not filtered by selection, no PR reviews or deletion reconcile, reported partial). A new **repository content lane** (`github.content_sweep`, every 5 min) captures exact bytes of every file at the head of the default branch (plus optional branches) of selected repositories: blobs are checked against git's own hash, there are per-scan generations (A→B→A safe, older scans refused), and deletes/renames become tombstones. Selection is done through `GET/PUT /v1/sources/github/repositories[/selection]`, enabled only when this tenant's own grant can read the repository. Files over 50 MiB, submodules and LFS content are listed but not fetched. Only branches are scanned. Rate-limit reset and Retry-After are honoured per installation. |
| Bitbucket, Slack, Notion, Granola, binary/Drive PDF | Integration in progress (per-provider agents) |
| Nango generic records lane | **Implemented** (`providers/nango-records`). Operator-declared Nango integrations and models only (`NANGO_RECORDS_CONFIG`), each verified against Nango's deployed sync functions. Sources that collide with a specialized module or a donor Nango integration are refused. Connect sessions are bound to the verified tenant. `/records` paging uses a durable cursor, Nango per-account quota cooldowns are persisted, and webhooks are HMAC-verified. Each record version is kept raw, plus a readable `sources/<source>/<pck>/<conn>/<model>/<id>.json` with tombstones. Coverage is **never complete**: Nango's cache holds the latest state only, and history depends on the sync function. File bytes are not downloaded. No Nango account exists yet, so every configured source reports `pending`. |
| Stripe | **Implemented.** Signed webhooks on a per-connection URL (the tenant comes from the URL, never the body), `event.id` dedupe, a 30-day events backfill (Stripe lists events for 30 days only; the donor's 3650-day setting overclaimed), a missed-event poll, and current object snapshots (customers, products, prices, subscriptions, invoices by default) at `sources/stripe/<acct>/<live\|test>/<resource>/<id>.json` with tombstones. Read-only keys; no Stripe-side changes; capability secrets redacted. Coverage: events are complete only from the window start; the webhook is partial until a signing secret is set. |
| Discord | **Implemented (official bot API only; user/selfbot tokens refused).** Explicit per-connection channel allowlist. Full history backfill plus forward polling with durable per-channel cursors. Discord's full `retry_after` is honoured, and a global limit pauses the connection. Messages are stored at `sources/discord/<guild>/<channel>/<yyyy-mm>/<id>.json` with raw versions. Edits and deletions are detected by a 7-day hourly rescan (no gateway), so `edits-deletions` stays partial. Without the Message Content intent, content is partial. A missing permission blocks only that channel. |
| WhatsApp / Instagram (personal, via Unipile) | **Implemented. Experimental, read-only, and disabled unless the operator sets `UNIPILE_PERSONAL_CONNECTORS_ENABLED=1`.** Unipile automates personal accounts through unofficial clients, which carries Terms of Service risk. Per-connection webhook URL and secret with an account ownership check. Readiness gate, resumable per-chat paging, immutable versions, WhatsApp deletions. Attachment bytes are fetched from the Unipile host only, capped at 25 MiB. Messages are stored at `sources/{whatsapp,instagram}-personal/<account>/<chat>/<yyyy-mm>/<id>.json`. History is **always partial**: WhatsApp gives only what linked-device sync provides, and Instagram only a limited recent slice. |
| Cursor background agents | **Implemented, read-only** (agents are never launched, followed up or deleted). The full `/v0/agents` listing is paged with a persisted cursor, and each agent's conversation is fetched. Changes become immutable raw versions. Agents gone from a completed listing are tombstoned. Signed webhooks are bound to a connection URL. Files are at `sources/cursor-agents/<conn>/<agent>/{agent,conversation}.json`. |
| Zoom | **Implemented** (port of the unmerged Aqueduct Zoom branch). User OAuth with single-use, tenant-bound state and rotating refresh tokens (no concurrent refresh). Cloud-recording transcripts in resumable 30-day windows: the poll covers the last 7 days every 5 minutes, the backfill up to 10 years. Per meeting UUID: `summary.md`, `transcript.md` and `meeting.json` under `sources/zoom/<title>-meeting-<hash>/`. **Transcripts only**: no audio, meeting chat or Zoom AI summaries. Retry-After is persisted. The bearer is never sent to the download CDN. |
| Linear | **Implemented, read-only** (personal API key; no mutations or webhook installation). Full paginated polling of issues, comments, projects and cycles, including archived ones. Delta watermarks advance after complete passes, with a 12-hour full reconcile. Donor snapshot ids are kept. An optional signed webhook is bound to its connection and organization. Remove, archive and missing objects are tombstoned. Rate and complexity limits are persisted. Files are at `sources/linear/<org>/{issues,comments,projects,cycles}/…`. |

## Account setup that needs a human

- **Nango:** sign-in and acceptance of Nango's terms are pending the user's explicit decision. No account was
  created.
- **Google Cloud (askshepherd.ai):** the organization's "Verify it's you" password challenge is pending the user. No
  OAuth client, API key or service account was created.
- **Google Workspace DWD:** needs a Workspace super-admin to authorize the service account's client ID.
- **Mac uploader:** installation and Full Disk Access are the user's action. Notarization is deferred.
